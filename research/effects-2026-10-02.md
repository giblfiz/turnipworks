# Turnip Works: A+ effects research (water, fire, smoke, fog)

2026-10-02. Fauna (Claude Opus 5.5, research subagent). Every price, license and version below was checked against the live page, the GitHub API or the npm registry today unless marked *(unverified)*. Confidence figures are on individual claims where they aren't directly quoted.

Context: three.js r170 (`three@0.170.0` in spawn-tuner), WebGLRenderer. WebGL must work, because the WebGPU build of Map Garden 2 black-screened in Firefox. The engine targets AGPL. Scenes are inn interiors 30–80 ft across, viewed top-down or at 3/4.

---

## 0. The finding that matters more than any single pick

**The r170 pin is now the main constraint, more than money.** Almost everything good shipped in 2026 needs a newer three.js, and the field has split in two:

| Item | three.js needed | Renderer |
|---|---|---|
| Three.js Water Pro (paid) | r181.1+ | WebGPURenderer (TSL); WebGL2 *backend* fallback |
| Three.js Sky Pro (paid) | r185+ | WebGPURenderer, WebGL fallback |
| three.quarks 0.17.x | >=0.182 | WebGL (WebGPU shaders added in 0.17) |
| three.quarks 0.16.0 | >=0.165 (**fine on r170**) | WebGL |
| three-fluid-fx | >=0.183 | GLSL **and** TSL pipelines |
| dgreenheck/threejs-particle-fluids | r184+ | **WebGPU only, no fallback** |
| pmndrs/postprocessing 6.39.5 | >=0.168 <0.187 | WebGLRenderer only |
| three-good-godrays 0.12.1 | 0.125–**0.182** | WebGLRenderer + pmndrs |
| N8AO 2.0.1 | r161+ recommended | WebGL only ("not yet compatible with WebGPU") |
| three.js core TSL examples (volumetric lighting, godrays, height fog, caustics, soft particles) | r18x dev (latest release **r186**, 2026-09-24) | WebGPURenderer; no compute, so they *should* run on the WebGL2 backend (~75%, not tested) |
| three.js core `webgpu_volume_fire` (added 2026-06-21) | r18x | **WebGPU compute required**; the example bails if `WebGPU.isAvailable()` is false |

So there are two coherent stacks:

- **Path A, "classic":** stay on `WebGLRenderer` and bump to **r182**, the version every WebGL-side library overlaps on (quarks 0.17, good-godrays ≤0.182, pmndrs <0.187, N8AO). Everything here is permissive OSS and runs everywhere, including Firefox.
- **Path B, "TSL":** move to `WebGPURenderer` (it falls back to a WebGL2 backend automatically, or always with `forceWebGL: true`). This unlocks Water Pro, Sky Pro, the coming Fire Pro, and core's new volumetric lighting and godrays. The cost: pmndrs/postprocessing and N8AO don't run on it (TSL post nodes replace them), and anything compute-based (core volume fire, particle-fluids) has **no** WebGL path at all. Note that Map Garden's black screen came from a WebGPU build. WebGPURenderer forced onto WebGL2 is a different code path, but it would still need its own Firefox smoke test.

**My recommendation (~70%): Path A now, at r182.** Keep each effect behind a small module interface so Path B can be tried as a spike later. The A+ look in a candle-lit interior comes mostly from *lit participating media*: firelight shafts through haze, soft smoke, AO, bloom. Path A covers all of that. Path B's exclusive wins are oceans, skies and compute fire, and those either don't fit indoor scenes or have no WebGL path.

## 1. WATER (troughs, wells, basins, maybe a pond outside)

**What "three.js water pro" is.** **Three.js Water Pro** by **Dan Greenheck** (Three.js Roadmap) — https://threejsroadmap.com/assets/threejs-water-pro, demo https://threejswaterpro.com/ (shader compile on first load is slow).
- **Price:** $99, one-time, lifetime updates (from search snippets: ~85% sure, since the product page shows no number). Water+Sky bundle is $239 (list $278, which implies Sky Pro is about $179).
- **Version:** v3.5.1, uploaded 2026-08-19. Actively maintained; v2.1 shipped in March and v3 later.
- **Tech:** TSL/WebGPU-first with a WebGL fallback ("nearly the same on both"). Needs r181.1+. FFT waves, three foam layers, caustics on the sea floor, buoyancy, boat wakes, an infinite clipmap LOD, 8 presets, deterministic multiplayer, "water masking for enclosed spaces."
- **License** (https://docs.threejswaterpro.com/license.html): perpetual and per-entity; all of the entity's developers are covered, with unlimited end products. *"Licensee shall NOT include the Software's Source Files in any open-source or source-available project."* *"Compiled Code may be incorporated into End Products and deployed publicly."* → **It cannot go in the AGPL repo.** At most it could be a closed, optional plugin that only our hosted build loads. Whether that sits cleanly beside AGPL is a legal question; ~60% defensible as a separate optional plugin, and worth sending to GPT/counsel before buying.
- **Fit:** poor. It's an **ocean**. It explicitly lacks rivers and shallow water; a "Rivers & Lakes add-on" is listed as *coming soon*. A 3-ft trough doesn't need FFT swells.

**Top tier for *our* scenes (free, MIT): assemble from three.js core.**
- Interactive heightfield ripples: `webgl_gpgpu_water` (in r170), or `webgpu_compute_water` on Path B. Demo: https://threejs.org/examples/#webgl_gpgpu_water.
- Plus reflection/refraction and flow: `Water2` / `webgl_water_flowmap` (in r170).
- Plus caustics on the trough floor: `webgpu_caustics` / `webgpu_volume_caustics` (core dev; TSL), or the classic Evan Wallace technique.
- Effort: a few days of shader work, so the money isn't the obstacle.

**Notch down:** **martinRenou/threejs-water** (BSD-3-Clause, demo https://martinrenou.github.io/threejs-water, last push 2021). It's a three.js port of Evan Wallace's pool with ripples and caustics, and its sibling `threejs-caustics` handles arbitrary meshes in the pool. Caveat: **evanw/webgl-water itself has no license** (all rights reserved), so take the technique, not his code. The port's BSD claim over derived code is murky (~50%).

**What makes it A+:** depth-tinted refraction of the trough floor, Fresnel reflection of the hearth light, caustics dancing on the stone, and ripples when a token or the cursor touches it. Interaction plus caustics is the whole trick.

## 2. FIRE (hearths, candles, torches)

**Top tier, commercial: Three.js Fire Pro (Greenheck)** — https://threejsroadmap.com/assets/threejs-fire-pro.
- **Status: "Coming Soon", waitlist only.** No price, no demo, no date.
- Promised: real-time volumetric fire and smoke simulation, emission from meshes, wind/turbulence/cooling, self-shadowing, WebGPU.
- Expect the Water Pro license, which means no source in the OSS repo (~80%). It's likely WebGPU-compute and so has no WebGL path (~65%). Worth joining the waitlist; don't plan around it.

**Top tier, available today (free, MIT): three.js core `webgpu_volume_fire`** (added to core 2026-06-21, PR #33848; r186 era).
- A real volumetric fire *simulation* coupled to `VolumetricLightingModel`.
- **WebGPU-compute only**: the example refuses to run without WebGPU. That makes it a Path B, progressive-enhancement option only.

**Top tier for WebGL (what I'd ship): `@wolffo/three-fire` plus three.quarks embers plus a flickering light.**
- **@wolffo/three-fire** — https://github.com/typeWolffo/THREE.Fire, demo https://threefire.netlify.app/, MIT, v1.4.0 on npm (2026-05-28), last commit 2026-10-01.
  - Raymarched procedural volumetric fire in a box (a modern TypeScript rewrite of mattatz/THREE.Fire).
  - GLSL entry `/vanilla` (three ≥r150) and TSL entry `/tsl/vanilla` (r168+).
  - Risk: a single small maintainer (26 stars), so vendor it.
- **Embers and sparks:** three.quarks (§3).
- **Light:** a noise-driven `PointLight` intensity/colour flicker plus a shadow map. This sells the fire more than the flame mesh does.
- **Candles:** a billboard flame shader with a few lines of noise (the "Lonely Candle" CodePen pattern: https://codepen.io/prisoner849/pen/XPVGLp). Cheap enough for dozens of candles.

**Notch down:** three.quarks flipbook fire (MIT), using our own or CC0 flipbook textures. Or mattatz/THREE.Fire (MIT, untouched since 2020).

**What makes it A+:** fire that *lights the room* (flicker-coupled lights and shadows), volumetric density instead of a flat card, heat-haze distortion above it, and embers that rise and die. For hearths, the coupling to light matters more than the flame itself.

## 3. SMOKE (chimney, snuffed candles, pipe smoke, room haze)

**Top tier: three.quarks** — https://github.com/Alchemist0823/three.quarks, demos https://demo.quarks.art/, docs https://docs.quarks.art/.
- **License:** MIT. 1,043 stars; v0.17.1 released 2026-05-21; actively maintained.
- **Features:** BatchedRenderer (few draw calls), soft particles (depth fade), sprite-sheet flipbooks, trails, sub-emitters, 20+ behaviours, JSON effects. The 0.17 line added WebGPU shaders, and `quarks.nodes` is an experimental WebGPU-compute node system.
- **Versions:** **0.16.0 runs on r170**; 0.17 needs r182.
- **Editor:** the web editor is at https://quarks.art/create. The old OSS `three.quarks-editor` repo (MIT) has been stale since 2023.
- **quarks.art plans:** Free (no JSON export, so useless to us), **Starter $12/user/mo** (JSON export), Pro $36/user/mo.
- **License flags:**
  - The ToS grants the site only "for your own personal, noncommercial use" and is silent on exported JSON. ~70% that JSON we author ourselves is ours, but it isn't written down.
  - Marketplace assets ($1-ish, e.g. FireBall) are under a "Quarks EULA" that I couldn't locate. **Treat marketplace effects as non-redistributable**: author our own, or ask Alchemist0823.
  - Cheap path: one month of Starter, author the inn's effects, export the JSON, cancel.

**Also top-tier for real volumetric smoke (Path B only):**
- **dgreenheck/threejs-particle-fluids** (MIT, demo https://dgreenheck.github.io/threejs-particle-fluids/, updated 2026-09-28). Covers liquids, soft bodies, cloth and smoke, but it's **WebGPU-only, r184+, no fallback**.
- Fire Pro smoke, when it ships.

**Notch down (free): the Coffee Smoke shader.** It's a scrolling-Perlin, twisted plane with a soft alpha.
- It's free in **three.js core** as `webgpu_tsl_coffee_smoke` (present in r170; TSL).
- The GLSL version is taught in **Three.js Journey** lesson 32 (and lesson 10 of the TSL course).
- Journey pricing: Three.js course $95, WebGPU & TSL course $45, bundle $120, lifetime, https://threejs-journey.com/. The license on lesson code isn't stated on the site, so reimplement rather than paste.
- Ideal for chimney wisps and tea mugs: one draw call each.

**What makes it A+:** soft particles (no hard intersection lines), lit smoke (six-way or normal-mapped flipbooks that take the firelight's colour), curl-noise motion, and smoke that bends with a draft.

## 4. FOG / ATMOSPHERE, including mouse-swirled fog

**What nobody sells:** a finished "3D fog that swirls when the mouse passes" product. Nothing exists commercially for three.js (~85%, after searches across threejsroadmap, threejsresources, Codrops, itch and gumroad). It's a build, and a very doable one.

**Top-tier recipe (all MIT or Zlib):**
1. **Density field:** **three-fluid-fx** — https://github.com/artcodev/three-fluid-fx, demo https://three-fluid-fx.artcreativecode.com/, MIT, v0.1.0 2026-05-12.
   - A Stam stable-fluids solver with vorticity confinement and BFECC. It ships GLSL **and** TSL pipelines and exposes `densityTexture` / `velocityTexture` for sampling in your own materials.
   - Needs **three ≥0.183**, so it forces a bump past r182 (it doesn't force WebGPU). It's young (153 stars), so vendor it.
   - On r170/r182: port **PavelDoGreat/WebGL-Fluid-Simulation** (MIT, 16.7k stars, last push 2024-11; the reference implementation). **bandinopla/threejs-fluid-simulation** (MIT) is already a three.js port of it.
2. **Coupling to the room:** raycast the cursor onto the floor plane and splat velocity and density into a 2D sim laid over the room's floor (a 30–80 ft room maps cleanly to a 256²–512² grid).
3. **Rendering:** a **ground-fog slab** raymarched in 4–8 steps over a fixed height range (0–4 ft). Density = sim density × height falloff × 3D noise. Light it by sampling the fire point lights. The sim is 2D, but in a top-down or 3/4 view it reads as volumetric (~80%).
   - Prior art for the method: Shahriyar Shahrabi, "Interactive Volumetric Fog With Fluid Dynamics and Arbitrary Boundaries."
   - Prior art for the mouse-trail → ping-pong fluid pattern in three.js: Codrops 2026-03-23, "Dual-Scene Fluid X-Ray Reveal."

**Light shafts (the biggest single A+ lever indoors):** **three-good-godrays** — https://github.com/Ameobea/three-good-godrays, demo https://three-good-godrays.ameo.design.
- Zlib license; v0.12.1 2026-08-06.
- Screen-space raymarched godrays that read **shadow maps**, from **PointLights** and DirectionalLights. That means torch and hearth shafts through haze, with occlusion by beams and furniture.
- Needs pmndrs/postprocessing and three ≤0.182 (another reason to pick r182).
- Cost: one shadow-casting light per godray source, so budget it for the hearth plus one or two windows.

**Path B equivalents (core, MIT):** `webgpu_volume_lighting` (+ `_rectarea`, `_traa`), `webgpu_postprocessing_godrays`, `webgpu_fog_height`, `webgpu_custom_fog_scattering`, `webgpu_postprocessing_fog`. These are TSL with no compute, so they probably run on the WebGL2 backend (~75%).

**Notch down:**
- Built-in `THREE.FogExp2`, plus a height-fog `onBeforeCompile` patch, plus scrolling-noise fog cards (soft particles) near the floor.
- Volume renderers: Donitzo/three.js-volume-renderer (MIT).
- **Avoid** Ameobea/three-volumetric-pass. It's nice-looking but has **no license** and was last pushed in 2023, so it can't ship.

**What makes it A+:** fog that is *lit* by the scene's fires and *shadowed* (shafts), and that reacts physically to motion (swirls, eddies, a wake behind a moving token). Static uniform fog reads as B-grade instantly.

## 6. Post stack (Path A)

- **pmndrs/postprocessing** v6.39.5 (2026-09-09), Zlib, three ≥0.168 <0.187. Bloom (for flames), SMAA, tone mapping, vignette, and a cheap GodRaysEffect (a screen-space sun disc, weaker than good-godrays).
- **N8AO** v2.0.1 (2026-08-10), CC0 in the repo (ISC on npm). Temporally stable SSAO with an `N8AOPostPass` for pmndrs. Demo: https://n8python.github.io/n8ao/example/. WebGL only. **Large win for interiors**: contact shadows under tables and barrels.
- **three-good-godrays**: above.
- 0beqz/realism-effects (SSGI/SSR, MIT): stale since 2024-02, so skip.

- **Dan Greenheck / Three.js Roadmap:**
  - Water Pro ($99) and Sky Pro (~$179): both WebGPU-first, both closed-source licensed.
  - Fire Pro and Rivers & Lakes: coming soon.
  - EZ Tree and Three Piñata: free.
  - particle-fluids: MIT, WebGPU-only.
  - None of it fits an indoor inn today except perhaps Fire Pro.

- **Codrops:** tutorials, not products. Relevant: fluid X-ray reveal (2026-03), "The Sleepers" atmospheric fog (2026-07), the fire shader in "3D World in the Browser" (2025-04). Repo licenses vary per demo, so check each one.
- **itch.io / Gumroad:** no three.js-specific VFX packs found. Everything there is Godot or Unity, and their flipbook textures usually forbid redistribution in source form.
