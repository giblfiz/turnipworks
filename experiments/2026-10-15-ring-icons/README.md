## Blind reads and their limits

Every final painting has an independent **gemini-3.1-pro-preview** read at 31 px on the game’s dark ground, without its filename, title or intended action. [READS.md](READS.md) records each actual interpretation and explicit review; raw prompts and responses remain under `reads/`. `accepted` means the requested action or its immediate visual operation was recognized. `learned` means the visible metaphor is usable but the exact command requires its menu context or a label. Neither is a claim of human usability testing.

The successful reads include damage, hide/reveal, lock/unlock, resize, replace, turn, give control, duplicate, sheet, faction, distance measurement and attachment. Some exact wall-family names and automatic selection remain learned contextual meanings, alongside fog depth versus general elevation, room ceiling versus object height, keeping through regeneration, caught-pawn announcement, marker meanings and measurement-template shapes. Dice read as dice; the selected object determines re-generation versus a game roll. Line alone can read as minus: its template palette context matters. Full per-variant evidence supersedes these grouped observations.

In round 1, we retained the first generic-tabletop protocol after it elicited global-toolbar guesses, then reran all final paintings under one neutral selected-piece contextual-menu protocol. Round 2 uses the requested D&D-condition question for conditions, and neutral material/count context for new submenu choices; the exact prompt is recorded per painting. No intended answer or metaphor is disclosed. Native generation errors (a signpost for a square, ornamental plaques or die glyphs for plain template geometry) were repainted rather than explained away. Superseded native images/specs are retained in `attempts/`; final provenance records exact prompts, own references where used, source hashes and every export hash. Images were generated with built-in imagegen; packaging only centers/resizes, never paints or removes backgrounds. No third-party icon references. External generation spend **$0**.

## Reproduce and verify

See [tools/README.md](tools/README.md). `tools/process.py --once` packages current sources and obtains missing reads. Explicit review decisions live in `review.json`. `python3 tools/validate.py` (from this directory) requires complete current sources, both sets, every size/hash, native alpha, matching exact provenance and successful per-picture-protocol reads with explicit accepted/learned judgments, unique sibling artwork, and all fourteen current-source confusion checks. Conditions require accepted readings; learned is not a waiver. Generated binaries follow repository policy: retained on disk and deployed, not committed; prompts, manifest, inventory, scripts and text evidence are committed. `tools/verify_live.py` checks every public size file byte-for-byte; `tools/verify_browser.py` decodes both preview sizes in Chromium.
